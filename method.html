計算方法と確かめ方

予想は参考情報です。的中や利益は約束しません。

馬券は20歳になってから、無理のない範囲で。

のめり込みが心配なときの相談先: JRA「ギャンブル等依存症対策」 https://www.jra.go.jp/company/social/disorder/

JRA・地方競馬の主催者とは関係ありません。

採点の方法

  • 前日（日本時間）に予想を作った全レースを採点します。Xに投稿したレースだけではありません。
  • Xに予想を投稿するレース: 中央の開催日は、中央の全レースと、中央の最終レースより後に発走する地方のレース（中央の開催中は地方を投稿しません）。地方だけの日は、地方の全レース。投稿しない地方のレースも、発走前の記録と採点は同じように行います。
  • 予想の投稿に載せるのは、印（◎○▲△☆）・予測ランク・照合の状態と、参考買い目（4つの型・1点100円の仮計算）です（9/26から）。指紋は投稿に書かず、公開リポジトリにだけ記録します。
  • Xの投稿の人気: 予想の投稿の「穴」の行の☆（印の順で2頭まで）に付ける人気は、投稿を作った時点の単勝オッズの低い順です（予想時点の人気）。結果の返信（印の着順・決着）と1日のまとめ（穴☆の3着内の最高○番人気）の人気は、同じ返信の「1番人気」の行と同じく、確定した単勝人気です。予想時点の人気は、確定した人気と違うことがあります。
  • ◎: 発走前に記録した予想の◎だけを使います。記録の中身から計算したハッシュが、発走前の記録と一致するものに限ります。
  • 1番人気: 確定した単勝人気の1位です。同じ人気なら確定オッズの低い方、さらに馬番の小さい方です。取消・除外の馬は対象外、競走中止・失格の馬は着外として数えます。
  • 出す値: 件数、勝率、3着内率、単勝と複勝の回収率、◎と1番人気が同じ馬だった数。参考買い目は、型ごとのレース数・的中・全点返還・仮計算の額・配当・回収率（下の「参考買い目の採点」）。
  • 回収率は、実際の払戻で100円ずつ買ったと仮定した計算で、実際の購入ではありません。予想時点のオッズは使いません。
  • 同着の1着は、どちらも勝ちとして数え、それぞれの単勝の払戻を使います。

参考買い目の採点

  • 規則v2（9/26から・夢は9/26から）: 堅め＝ワイド ◎-○・◎-▲（2点）。本線＝馬単マルチ ◎⇔○・◎⇔▲・◎⇔△（△は印の順で最大2頭。△2頭で8点・1頭で6点・0頭で4点）。広め＝3連複 ◎○▲△△ のBOX（10点。△1頭で4点・0頭で1点）。夢＝3連複フォーメーション ◎ - ○▲△ - ☆（△は印の順で最大2頭、☆は印の順で最大2頭。点数は列の頭数のかけ算で、△2頭・☆2頭なら8点。☆のいないレースでは出しません）。☆は夢だけで使います（予想の投稿で馬番を見せた☆と同じ馬です）。
  • ◎○▲がそろわないレースには出しません。広めと夢は、組んだ時点の出走頭数（取消・除外を除く）が7頭以下のレースでは出しません。
  • 買い目は、発走前に記録した印とこの規則だけで機械的に決まります（レースごとに選び直しません）。採点では、記録した買い目が、発走前に記録した印と規則から組み直したものと同じときだけ数えます。
  • 1点100円の仮計算で、実際の購入ではありません。的中と配当は、確定した配当（100円あたり）で決めます。
  • 取消・除外の馬を含む点は返還として、仮計算の額から外します。全部の点が返還になった型は「全点返還」と数えます。競走中止・失格の馬は返還にせず、外れとして数えます。
  • 着順では的中でも配当を取れていない型は、額を推測せず「確認中」とし、回収率を出しません。
  • 通算に数えるのは、規則の開始（9/26）以後に発走し、参考買い目つきの予想をXに投稿できたレースのうち、GitHub側の時刻で発走前に記録できたものだけです（◎の累計と同じ条件）。Xに投稿しなかったレースも日別のページには載せますが、通算には入れません。
  • 規則の中身は、公開リポジトリの reference-tickets-v2.json にあります（sha256 は README に載せています）。前の版の規則のファイルも残しています。

除外のルール

採点できないレースには理由を1つだけ付け、上から順に判定します。予想の件数＝採点した件数＋除外の合計です。

表示中身
照合不成立朝や発走前の照合で止まり、予想を出していない
封印なし発走前の記録が無い
発走後の封印記録がすべて発走時刻より後
ハッシュ不一致記録の中身のハッシュが合わない
◎なし記録の中身に◎が無い
結果なし確定結果を取れていない（翌朝に取り直す）
◎取消◎が取消・除外（返還になるため外す）
払戻なし単勝の払戻がそろっていない

公開開始からの累計の数え方

公開開始日（9/26）以降に採点できたレースのうち、GitHub側の時刻で発走前に記録できたものだけを数えます。時刻を取れなかったものは「GitHub時刻未取得」とし、数えません。公開開始日より前の日の予想は、日別の一覧にも累計にも載せません。

モデルの版

版の名前は、予想に使ったモデルの種類（ensemble・legacy・features-fallback）と、そのモデルを見分けるための12桁のハッシュです。モデルを入れ替えると名前が変わります。「（版の記録なし）」は、版を記録する前に作った予想です。

確かめ方

  1. 発走前に、予想の中身（場・R・発走時刻・モデルの版・印の馬番・照合の結果）に128ビットの乱数を足したJSONを作り、その sha256（指紋）を公開リポジトリの ledger ブランチに1行ずつ push します。
  2. 9/26からXの予想投稿には指紋を書きません。投稿したレースと台帳の行は、日付と race_id で照らし合わせます（日別のページの表にレースごとの指紋を載せています。結果の後に出す中身にも場・R・発走時刻が入っています）。
  3. 結果の後に、中身のJSONを reveals/ に出します。中身から計算し直した sha256 が、発走前の指紋と一致すれば、発走前の予想から変えていないことが確かめられます。
git clone -b ledger https://github.com/zb-tb/umagami-ai.git ledger
python3 ledger/verify.py ledger
python3 ledger/verify.py ledger --date 20260926

verify.py は Python 3 の標準ライブラリだけで動きます。指紋の計算は、キーを辞書順に並べ替え、区切りの空白なし、非ASCII文字はそのままにしたJSONのUTF-8に sha256 です。

GitHub側の時刻

  • git のコミット日時は書く側が自由に付けられるため、証拠には使いません。GitHub が記録した push の時刻（リポジトリのアクティビティ）を使います。
  • アクティビティで見られる期間には制限があり、保持期間は確かめられていません。このページには、取得した時刻を控えとして載せています。
  • 強制pushと削除の禁止: 2026-09-25 から ledger と main で禁止する設定にしています。
