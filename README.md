# 採点ページと指紋の記録

AIの競馬予想（◎）を発走前に記録し、翌朝に機械的に採点して公開するためのリポジトリです。

- `main` ブランチ: 採点ページ（GitHub Pages）
- `ledger` ブランチ: 発走前の指紋（`fingerprints/YYYYMMDD.jsonl`）と、結果の後に出す中身（`reveals/YYYYMMDD/<race_id>.json`）

予想は参考情報です。的中や利益は約束しません。馬券は20歳になってから、無理のない範囲で。

## 指紋とは

1. 発走前に、予想の中身（場・R・発走時刻・モデルの版・印の馬番・照合の結果）に128ビットの乱数（nonce）を足したJSONを作ります。
   10/27 14:00から発走するレースは、印の馬番に荒れ狙いの印（`marks` の `upset`。○▲△の馬番）も入ります（それより前のレースの中身の形は変わりません）。
   モデルの版は、予想に使ったモデルの種類と、そのモデルを見分けるための12桁のハッシュです（版を記録できなかった予想は null）。
2. そのJSONの sha256 を「指紋」として、`ledger` ブランチの `fingerprints/YYYYMMDD.jsonl` に1行ずつ push します。
3. 9/26からXの予想投稿には指紋を書きません。投稿したレースと台帳の行は、日付と race_id で照らし合わせます（採点ページの日別の表にレースごとの指紋を載せています。結果の後に出す中身にも場・R・発走時刻が入っています）。
4. 結果（1〜3着）が確定した後に、中身のJSONを `reveals/` に出します。翌朝になっても結果を取れないレースは、結果なし（`result: null`）で出します。
5. 中身から計算し直した sha256 が、発走前に記録した指紋と一致すれば、発走前の予想から変えていないことが確かめられます。

乱数を足しているのは、発走前の指紋から印を総当たりで推測されないようにするためです。

## 直前の予想

発走の約15分前に、直前の予想を、朝の予想の投稿への返信で出します。点数は、馬体重が出そろった後の最初の回（発走の約25分前。そのときにそろっていなければ約15分前）に、モデルで1回だけ計算し直します。◎はその点数の最も高い馬です。ほかの印（○▲△☆）は、出す直前に取ったオッズ（取れなかったときは前の回に取ったオッズ）で組み直し、参考買い目はその印から決めます。10/27 14:00からは、見えている○▲△（本線の印）も◎と同じ点数の順で決め、オッズで組み直すのは荒れ狙いの印と☆です。直前の予想も発走前に指紋を記録します。同じ race_id の別の版として1行足し、行と、結果の後に出す中身の版に `"stage": "final"` を付けます（中身のJSONの形と指紋の計算は朝の予想と同じです）。採点は朝の予想と分けます。

## 参考買い目の規則

9/26から、予想の投稿に参考買い目（3つの型・1点100円の仮計算。実際の購入ではありません）を載せています。買い目は、発走前に記録した印と規則だけで機械的に決まり、レースごとに選び直しません。

- 堅め: ワイド ◎-○・◎-▲（2点）
- 本線: 馬単マルチ ◎⇔○・◎⇔▲・◎⇔△（△は印の順で最大2頭。△2頭で8点・1頭で6点・0頭で4点）
- 広め: 3連複 ◎○▲△△ のBOX（10点。△1頭で4点・0頭で1点）。出走7頭以下のレースでは出しません
- ◎○▲がそろわないレースには出しません。☆は夢だけで使います（9/26から）
- 取消・除外の馬を含む点は返還として、仮計算の額から外します。競走中止・失格は返還にしません

## Xの投稿の人気

- 予想の投稿の「穴」の行の☆（印の順で2頭まで）に付ける人気は、投稿を作った時点の単勝オッズの低い順です（予想時点の人気）。
- 結果の返信（印の着順・決着）と1日のまとめ（穴☆の3着内の最高○番人気）の人気は、同じ返信の「1番人気」の行と同じく、確定した単勝人気です。
- 予想時点の人気は、確定した人気と違うことがあります。

## 確かめ方

Python 3 があれば、標準ライブラリだけで確かめられます。

```
git clone -b ledger https://github.com/<owner>/<repo>.git ledger
python3 ledger/verify.py ledger
python3 ledger/verify.py ledger --date 20260926
```

- `一致`: 中身のハッシュが、発走前の指紋と同じ
- `未開封`: まだ結果の後の中身を出していない（結果の確定後、その日の夜か翌朝に出します。記録を一時的に止めている間は、再開した後に出します）
- `不一致`・`台帳に無い開封`: 記録と中身が合っていない

指紋の計算は、キーを辞書順に並べ替え、区切りの空白なし、非ASCII文字はそのままにしたJSONのUTF-8に sha256 です（`verify.py` の `canonical_json`）。

## 時刻の見方

- git のコミット日時は、書く側が自由に付けられるため、証拠には使いません。
- GitHub が記録した push の時刻を使います。リポジトリのアクティビティで見られます。
  `https://api.github.com/repos/<owner>/<repo>/activity?ref=refs/heads/ledger`
- アクティビティで見られる期間には制限があり、保持期間は確かめられていません。採点ページには、取得した時刻を控えとして載せています。
- 採点ページの「公開開始からの累計」には、GitHub側の時刻で発走前に push できたレースだけを数えます。時刻を取れなかったレースは「GitHub時刻未取得」とし、累計に入れません。
- `ledger` と `main` は、強制pushと削除を禁止する設定にします（設定した日は採点ページに載せます）。
